# Nexmon CSI extractor

Standalone Raspberry Pi CSI capture, SQLite storage and optional plain TCP
forwarding to one or more control servers. Every destination has its own sender
subprocess and bounded queue so a slow receiver cannot delay local recording or
other destinations.

The application contains only radio setup, packet decoding, MAC filtering,
database storage, forwarding and capture lifecycle management. ML detection,
calibration, simulation, MQTT, TLS/authentication, server-managed configuration,
vault management, Wi-Fi recovery, retention cleanup and their dependencies have
been removed.

## Quick start

On a Pi with the existing Nexmon firmware installed:

```bash
cd /home/pi/secure_mount/rpi-csi-rx
/home/pi/.pyenv/versions/nexmon-csi/bin/python -m pip install -e .
test -f .env || cp .env.example .env
nano .env
chmod +x csi_extract.sh
sudo ./csi_extract.sh
```

Press Ctrl+C to stop. For a background capture, use
`sudo ./csi_extract.sh --stop`. The launcher uses the nexmon-csi virtual
environment and gracefully replaces a previous capture started by this version
on the same interface.

See [the student guide](docs/CSI_Capture_Student_Guide.md) for background logging,
named databases, data inspection, stopping and troubleshooting.

## Configuration

Edit the project-root `.env` and restart. Explicit process environment variables
override the file; `--env-file /absolute/path/.env` selects a different file.

```dotenv
NEXMON_IFACE=wlan0
NEXMON_MONITOR_IFACE=mon0
CHANNEL_NUM=9
BANDWIDTH=20
NEXMON_CONFIG_LENGTH=106
TX_MAC_ADDRESS=
CSI_DAILY_DIR=/home/pi/secure_mount/data/csi_daily

SEND_CSI_DATA=false
CONTROL_IP=192.168.0.254
TCP_PORT=8080
```

Set `SEND_CSI_DATA=true` to enable **unencrypted TCP forwarding**. Local storage
is always enabled. The server must expose its legacy CSI TCP listener; a
TLS/authenticated-only listener will not accept these messages. MQTT registration,
receiver tokens and certificate settings are no longer used.

For several destination machines, use commas between the IP addresses:

```dotenv
SEND_CSI_DATA=true
CONTROL_IP=192.168.1.100,192.168.1.101
TCP_PORT=8080
SOCKET_TIMEOUT=5
SEND_QUEUE_BATCHES=20
SEND_SHUTDOWN_TIMEOUT_SEC=3
```

All destinations use the same TCP port and must run a compatible Nexmon receiver.
A single IP also works. IPv4 and IPv6 numeric addresses are accepted; whitespace
around commas is allowed and duplicate addresses are removed. Empty list entries,
invalid IPs and hostnames are rejected when forwarding is enabled. Restart capture
after changing these settings. `SEND_CSI_DATA=false` creates no sender processes
or TCP connections.

`SOCKET_TIMEOUT` is the connect/send timeout per worker (greater than 0 and at most
30 seconds). `SEND_QUEUE_BATCHES` limits each destination to 20 pending batches by
default. `SEND_SHUTDOWN_TIMEOUT_SEC` is a shared drain budget across all workers
(default 3 seconds, configurable from 0 to 10 seconds). `RX_MAC_ADDRESS` keeps its
existing meaning: blank reads the MAC of `NEXMON_IFACE`.

The existing channel, interface, server address and flush interval are preserved
in this checkout's simplified `.env`. See `.env.example` for all supported
settings. No JSON transmitter/configuration file is required.

## Firmware and packet compatibility

The parser preserves this codebase's BCM43455c0 Gain Recovery V2 layout:
70 header bytes, followed by little-endian signed int16 complex samples.
This layout matches the [gain firmware's CSI frame definition](https://github.com/T3rO/nexmon_csi_gain/blob/master/src/csi_extractor.c).
It is not a decoder for stock 18-byte Nexmon headers or other chipsets' packed
floating-point formats.

The existing 20/40/80 MHz effective-subcarrier ordering and eleven-field gain
blob are unchanged. The complete Nexmon header is also saved for later analysis.
There is no FeitCSI process or FEITCSI_FORMAT setting.

The Pi needs `mcp`, `nexutil`, `iw` and `ip` on the root user's PATH.
`NEXMON_CONFIG_LENGTH=106` preserves the old launcher's setting. The length
must match the installed firmware and the parameters generated by `mcp`;
startup checks this before applying parameters. Core and spatial-stream masks
remain `0x1`. Up to four transmitter filters are also passed to firmware;
longer lists are enforced in Python.

## Databases

- `sudo ./csi_extract.sh`: UTC daily files under `CSI_DAILY_DIR`.
- `sudo ./csi_extract.sh experiment`: one
  `experiment-YYYY-MM-DD-HH_MM_SS.db` in the parent of `csi_daily`
  (or directly in `CSI_DAILY_DIR` if its name is different).
- `sudo ./csi_extract.sh /home/pi/csi_database/experiment`: one timestamped
  file at the chosen absolute path prefix.

Every database has its own `MAC_addr` table. Join it to `CSI_frame` using
`MAC_addr.id = CSI_frame.mac_id`; IDs are not global across databases.
Named captures do not rotate at midnight. Daily files are opened lazily when
frames are committed.

`CSI_frame` stores `csi_value`, `mac_id`, integer `rssi`, `gain`,
UTC-microsecond `timestamp`, `bandwidth`, `num_subcarriers` and
`nexmon_header`. IQ is uncompressed interleaved little-endian int16 real/imaginary
pairs (56/114/242 subcarriers at 20/40/80 MHz). Gain is retained because it contains
real Nexmon measurements required by existing consumers.

Transactions flush at `DB_BATCH_SIZE` or `WRITE_INTERVAL_MS`, including during
quiet periods. Shutdown flushes pending frames and checkpoints SQLite WAL.
A disk-write failure stops capture; historical files are never deleted
automatically.

Older daily files without `MAC_addr` cannot be appended safely. Keep their old
main `database.db` for MAC lookup and choose a new directory or named run.

## Control-server wire protocol

Each committed batch is sent using a new TCP connection:

```text
4-byte big-endian unsigned payload length
pickle.dumps(rows, protocol=pickle.HIGHEST_PROTOCOL)

rows = [
    [csi_bytes, tx_mac_bytes, rx_mac_bytes, rssi, timestamp_us, gain_bytes],
    ...
]
```

Both MACs are six-byte values. The gain blob consists of eleven little-endian
signed int16 values in this order:

```text
lna1_1, mix_1, dvga_1, lna1_2, mix_2, lna1_9,
lna1_10, mix_10, lpf1_10, dvga_10, agcGain
```

This keeps the existing Nexmon six-field row format, CSI bytes, gain bytes and
pickle protocol. Existing Nexmon receivers can continue decoding the messages.

Each committed batch is offered to every destination using a nonblocking queue
call. Background queue feeders handle IPC; row conversion, pickle serialization,
TCP connections and network sends all run inside the sender subprocesses. Spawned
workers do not inherit the capture socket or SQLite connection. An offline or
blocked destination can fill only its own queue. A full queue or exited worker
drops that destination's forwarded copies while the local database retains its
committed frames. Other destinations keep sending independently.

Forwarding is best effort. Every `STATS_LOG_INTERVAL_SEC`, logs report each
destination's `sent`, `failed`, `dropped` and `pending` frame counts. `sent` counts
completed TCP writes, not confirmed server database inserts; there is no automatic
replay or acknowledgement. If a sender process exits, restart capture to restore
that destination. A failure to start the forwarding workers is logged and local
capture continues.

Graceful shutdown first flushes pending CSI to disk. It gives all sender processes
a shared `SEND_SHUTDOWN_TIMEOUT_SEC` drain budget, then stops remaining workers
with up to two extra seconds for process cleanup. Remaining remote copies are
counted as dropped. Workers also exit when they detect the capture parent has
gone away, subject to a current socket operation timing out. Keep the local
database as the source record.

## Development

Python 3.9+; the only runtime Python dependency is python-dotenv.

```bash
python -m pip install -e '.[dev]'
python -m pytest -q
python -m ruff check src tests
python -m ruff format --check src tests
```

Tests cover synthetic 20/40/80 MHz packets, legacy gain/wire compatibility,
malformed packets, filters, UTC rollover, named files, atomic writes, shutdown
flushes, forwarding outages, multiple TCP destinations, blocked sockets, full
queues and bounded subprocess shutdown. Real sender subprocesses and loopback
listeners verify the legacy wire bytes. Pi radio commands and capture signalling
are mocked; actual hardware capture must be verified on the Pi.
